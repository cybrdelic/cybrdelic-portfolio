Design System¶

Cybrdelic Portfolio incorporates a comprehensive design system that ensures visual consistency while providing flexibility for creative expression. This document outlines the key design principles and components.

Design Principles¶

The design system follows four core principles:

  1. Cyberpunk Aesthetic with Professional Polish

    • Bold, high-contrast visuals balanced with professional readability
    • Futuristic elements that don't sacrifice usability

  2. Terminal-Inspired Interaction

    • Command-line inspired navigation and feedback
    • Typewriter and glitch effects that feel tactile

  3. Performance-First Approach

    • Minimal dependencies for fast loading
    • Progressive enhancement for broader device support

  4. Accessibility Without Compromise

    • Maintains WCAG compliance while preserving visual style
    • Keyboard navigation and screen reader support

Adding a New Project¶

  1. Create the Content Structure

    $ mkdir -p content/projects/new-project-id/flows

  2. Add Markdown Documentation Files

    Create markdown files for each aspect of the project:

    $ touch content/projects/new-project-id/flows/architecture.md touch content/projects/new-project-id/flows/features.md touch content/projects/new-project-id/flows/installation.md

  3. Add Project Image

    Place the project image in the static images directory:

    $ cp path/to/image.jpg static/images/new-project-id.jpg

  4. Update Project Definition

    Edit to add the new project to the function:

    $ Project::new( "new-project-id", "Project Title", "Project Subtitle", "Full description of the project...", "/static/images/new-project-id.jpg", "Image caption", "svg-icon-path", // Path for the SVG icon or use an existing one vec!["Technology 1", "Technology 2"], vec![ ("GitHub", "https://github.com/username/repo"), ("Demo", "https://demo-link.com"), ], vec![ ( "Feature Title", "Feature description", "feature-icon-path" ), // Add more features as needed ], ( "Architecture description", "Implementation details", "Challenges faced" ), vec!["keyword1", "keyword2"], scan_flow_configs("new-project-id")?, // Automatically scans flow markdown files vec![ ( "Future Feature", "Description of planned feature", "Timeline" ), // Add more future features as needed ], )?

  5. Create SVG Icon (Optional)

    For custom animated icons, create a new file:

    $ touch templates/components/animated_icons/new-project-id.html

    Add the SVG markup to this file.

  6. Rebuild and Test

    $ ./restart.sh

    Visit http://localhost:0/projects/new-project-id to verify the new project page.

Static Site Generation¶

This document explains how the static site generation works in the Cybrdelic Portfolio project, covering the build process, configuration options, and deployment strategies.

Overview¶

The Cybrdelic Portfolio can operate in two distinct modes:

  1. Development Mode: A live Axum web server for local development
  2. Production Mode: Static site generation for deployment to web hosting

The static site generation process converts the dynamic Rust application into a collection of HTML, CSS, JavaScript, and image files that can be hosted on any static file server, including GitHub Pages.

The Build Process¶

The static site generation is implemented in . This standalone binary performs the following steps:

  1. Initialize the Tera Template Engine

    • Loads all templates from the directory
    • Parses template syntax and prepares rendering functions

  2. Load Content Data

    • Retrieves project definitions from
    • Loads career timeline data from
    • Processes all markdown files in

  3. Configure Base Path

    • Sets the URL base path for all links and assets
    • Typically "/" for root deployment or "/repository-name/" for GitHub Pages

  4. Render Pages

    • Renders the main index page with all projects and timeline
    • Creates project detail pages for each project
    • Outputs HTML files to the directory

  5. Copy Static Assets

    • Creates necessary directories in
    • Copies all static files (CSS, JS, images, fonts)
    • Maintains the directory structure

Running the Static Build¶

To generate the static site:

$ cargo run --bin build-site

This will create or update the directory with all generated files. The process is logged to the console, showing:

Architecture¶

Cybrdelic Portfolio is built with a modern, performance-focused architecture designed to deliver a seamless, interactive user experience while maintaining excellent SEO and accessibility.

System Overview¶

Core Components¶

Axum Web Server¶

The application is powered by Axum, a modern Rust web framework:

  • Async Runtime: Built on Tokio for high-performance, non-blocking I/O
  • Type-Safe Routing: Compile-time route verification
  • Middleware Stack: Logging, compression, and security enhancements
  • Error Handling: Graceful error recovery and reporting
Tera Templating¶

The templating system uses Tera, a Jinja/Django-inspired template engine:

  • Component-Based Structure: Modular templates with inheritance
  • Context Injection: Dynamic data binding from Rust to templates
  • Filters and Macros: Powerful transformation capabilities
  • Conditional Rendering: Intelligent display logic
Content Management¶

Content is managed through a file-based system:

  • Markdown Processing: Custom parser with extended syntax support
  • Project Metadata: Structured data for projects and features
  • Content Organization: Logical directory structure for maintainability
  • Static Content Generation: Pre-processed at build time for performance
Front-End Architecture¶

The front-end is built with a modern, lightweight approach:

  • Vanilla JavaScript: No heavy frameworks, just focused functionality
  • CSS Architecture: Modular CSS with custom properties
  • Progressive Enhancement: Core functionality works without JavaScript
  • Performance Optimization: Asset minification and efficient loading

Data Flow¶

  1. Client makes a request to the Axum server
  2. Router directs request to the appropriate handler
  3. Handler queries the content store for needed data
  4. Tera renders templates with the data context
  5. Server responds with the rendered HTML
  6. Client-side JavaScript enhances the experience
